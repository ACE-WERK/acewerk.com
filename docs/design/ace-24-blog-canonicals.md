## 0. User Story

As a **search-engine crawler** (and as a **visitor** whose cached/shared blog URLs may be reached via `dev.acewerk.com` or `acewerk.com`), I want every blog page to declare exactly one `<link rel="canonical">` pointing at the production URL of the same page, so that blog index and post content do not count as duplicate/fragmented pages in search, and the blog behaves like the rest of the site (which already self-canonicals correctly).

## 1. The defect (verified)

At `dev-origin/main` @ `e3e160e`:

- `blog/index.html`, `blog/dev-fixture-short/index.html`, `blog/dev-fixture-long/index.html`, `blog/dev-fixture-truncation/index.html`: **zero** `<link rel="canonical">` occurrences. The only string "canonical" on any blog page is the CSS comment `/* canonical tokens (reused) */` in the inlined `<style>` (also line 320 of `scripts/build_blog.py` — it is a CSS comment, not a tag, and stays untouched).
- All four non-blog pages already canonical correctly (the D1 reference pattern):

  | Page | Canonical |
  |---|---|
  | `index.html` | `https://acewerk.com/` |
  | `services/index.html` | `https://acewerk.com/services/` |
  | `our-team/index.html` | `https://acewerk.com/our-team/` |
  | `contact/index.html` | `https://acewerk.com/contact/` |

All four blog pages are generated by `scripts/build_blog.py`; their `<head>` is rendered by a **single** function, `render_head(title)` at **line 952** (baseline). It is called from exactly two places:

- `build_index_page(...)` — call at **line 1189** (function def line 1135)
- `build_post_page(post)` — call at **line 1238** (function def line 1224)

Baseline `render_head` (lines 952–961) emits, in order: doctype, `<html lang="en">`, `<head>`, charset meta, viewport meta, `<meta name="robots" content="noindex, nofollow">`, `<title>…</title>`, then font preloads + stylesheet + inlined `<style>`. There is **no** canonical line and **no parameter** by which the function could know the page URL.

## 2. Decisions (FROZEN)

### D1 — Canonical URLs use the PROD base, one per page, page-specific.
Two-repo rule (dev pages canonical to production; prod pages will canonical to themselves — D5):

- blog index → `https://acewerk.com/blog/`
- each post → `https://acewerk.com/blog/<slug>/` where `<slug>` = the post's `slug` frontmatter value (established key in the build: `post["slug"]`, used at build_blog.py lines 281, 1105, 1536; output dir is `blog/<slug>/index.html`).

For the three committed fixture posts (verified frontmatter): `https://acewerk.com/blog/dev-fixture-short/`, `https://acewerk.com/blog/dev-fixture-long/`, `https://acewerk.com/blog/dev-fixture-truncation/`.

### D2 — Minimal mechanism: `render_head(title, canonical=None)`; tag emitted immediately after the `<title>` line.
Exact new signature and emission rule:

```python
def render_head(title, canonical=None):
    ...
    "  <title>" + html.escape(title) + "</title>\n",
    ]
    if canonical:
        parts.append('  <link rel="canonical" href="' + canonical + '">\n')
    parts += [
        '  <link rel="preload" href="/assets/fonts/orbitron-500-latin.woff2" as="font" type="font/woff2" crossorigin>\n',
        ...
```

- **Exact line format** (2-space indent, double quotes, absolute URL, trailing newline):
  - index: `<link rel="canonical" href="https://acewerk.com/blog/">`
  - post: `<link rel="canonical" href="https://acewerk.com/blog/<slug>/">`
- **Position**: the tag is inserted **immediately after the `<title>…</title>` line and before the first font `<link rel="preload">` line** — i.e. between the two bracketed list sections shown above. Do not append at the end of the parts list and do not reorder existing lines.
- **Back-compat**: `canonical` defaults to `None` and is truthiness-gated (`if canonical:`) → a call without a URL emits head **identical to today** (zero canonical tags). No other default-behavior change.
- **Call sites (the only two):**
  - `build_index_page` (line 1189): `render_head(title)` → `render_head(title, canonical="https://acewerk.com/blog/")`
  - `build_post_page` (line 1238): `render_head(title)` → `render_head(title, canonical="https://acewerk.com/blog/" + post["slug"] + "/")`

Rejected alternatives: (a) hardcoding the URL inside `render_head` from `title` — brittle, couples head to page-kind heuristics; (b) a separate `render_canonical(url)` helper called from each builder — one extra function for one line; (c) appending the tag at the end of `<head>` — deviates from the explicit position locked above. D2 as locked is the smallest change that keeps a single source of truth in the template.

### D3 — Regenerate the 4 committed pages; drift protocol = ACE-22 A8 / ACE-23 D4.
After the D2 edits, Dev MUST run `python3 scripts/build_blog.py` so that `blog/index.html` + `blog/dev-fixture-{short,long,truncation}/index.html` are the generator's actual output (repo invariant: committed pages == `build_blog.py` output). Then diff regenerated vs committed: **expected delta is exactly +1 line per page — the canonical line (D2), and nothing else.** If regeneration surfaces any drift beyond that line, do **not** absorb it silently: report it in the Dev handoff and hand-patch the affected pages to add only the canonical line (identical patch, same protocol as ACE-22 E5 / ACE-23 E5).

### D4 — Scope guardrail (frozen).
The complete change set is: the `render_head` signature + conditional append in `scripts/build_blog.py`, the two call-site arguments, and the 4 regenerated HTML files (plus this spec doc). **Do NOT touch:** the `noindex` meta (stays on all blog pages), `robots.txt`, `sitemap.xml`, any other meta tag, the font preloads, the inlined `<style>`/CSS (including the `/* canonical tokens (reused) */` comment at line 320), the nav, any non-blog page, the homepage, and `src/*.html`. No new dependencies.

### D5 — Prod behavior: same value, no dev/prod divergence.
When this later ships to prod (Release t_262d51cd, PARKED pending Illya's explicit approval), the identical prod-based canonical is correct: prod blog pages will canonical **to themselves** (`https://acewerk.com/blog/…`), which is the standard self-canonical form. No config, flag, or per-environment canonical value is introduced. Note for Release: prod currently has only `blog/index.html` (fixture posts were dropped in the ACE-23 rollback), so prod gains exactly one canonical (the index's) on merge.

## 3. Acceptance criteria (testable)

**A1 — render_head contract.** Given `scripts/build_blog.py` per D2: when called **with** a non-empty URL, the returned head contains **exactly one** `<link rel="canonical" href="<that URL>">` line, in the D2 position; when called **without** a URL (default), it contains **zero** canonical lines and is byte-identical to the baseline head. (Verify by importing the module and calling `render_head("T")` vs `render_head("T", canonical="https://acewerk.com/blog/")`.)

**A2 — Blog index page.** Regenerated `blog/index.html` contains exactly one canonical:
`  <link rel="canonical" href="https://acewerk.com/blog/">`

**A3 — Post pages.** Each regenerated post page contains exactly one canonical matching its own slug:
- `blog/dev-fixture-short/index.html` → `  <link rel="canonical" href="https://acewerk.com/blog/dev-fixture-short/">`
- `blog/dev-fixture-long/index.html` → `  <link rel="canonical" href="https://acewerk.com/blog/dev-fixture-long/">`
- `blog/dev-fixture-truncation/index.html` → `  <link rel="canonical" href="https://acewerk.com/blog/dev-fixture-truncation/">`

**A4 — Exactly one, nothing else.** On all 4 blog pages: `grep -c 'rel="canonical"'` = **1** (0 or 2+ fails). The `<head>` delta vs baseline is only the one canonical line: `noindex` meta, charset, viewport, all font preloads, stylesheet, inlined `<style>`, `<title>`, and every `<body>` line unchanged (byte-identical apart from the inserted line).

**A5 — Change set + push.** `git status`/`git show` on the final commit touches **exactly**: `scripts/build_blog.py`, `blog/index.html`, `blog/dev-fixture-short/index.html`, `blog/dev-fixture-long/index.html`, `blog/dev-fixture-truncation/index.html`, and `docs/design/ace-24-blog-canonicals.md` (this spec). No other file. Committed and pushed to `dev-origin/main`; the commit is visible on the remote (`git rev-parse dev-origin/main` after push includes it) and live at `dev.acewerk.com` once Pages propagates.

## 4. Edge cases

- **E1 — Back-compat / other callers.** `canonical=None` is the default, so any future (or current) caller of `render_head` that passes no URL is unaffected. Today the only callers are the two D2 call sites; both are updated.
- **E2 — `noindex` + canonical coexistence is intentional.** Dev pages keep `<meta name="robots" content="noindex, nofollow">` **and** carry prod canonicals — the same combination the 4 non-blog dev pages already ship (verified). Noindex suppresses indexing; the canonical still declares the canonical URL for any crawler or tooling that sees the page. Do not "fix" this apparent contradiction.
- **E3 — Fixture slugs vs future real slugs.** Canonicals are derived from `post["slug"]` at build time, so every future post page auto-canonicals correctly with zero further edits. Fixture names are not special-cased anywhere.
- **E4 — URL construction.** Slugs are filesystem directory names (`content/posts/<slug>.md` → `blog/<slug>/index.html`), so they are URL-safe by construction (lowercase alphanumerics + hyphens in practice). No URL-encoding or escaping step is added to the canonical value; `post["slug"]` is concatenated raw (consistent with line 1536's dir construction). Titles (which DO contain spaces/`&`) are **not** part of canonicals — only slugs are.
- **E5 — Regeneration drift.** Per D3: any delta beyond the canonical line on any regenerated page is reported, not absorbed; hand-patch identically. The generator is deterministic for a given `content/posts/` state, so drift would indicate an environment/content difference, not a template bug.
- **E6 — Non-blog pages and prod repo.** Nothing outside `scripts/build_blog.py` + the 4 blog pages changes. Non-blog canonicals (A5 reference table in §1) remain byte-identical. Prod (`origin`) is untouched until the PARKED Release runs, and there only `blog/index.html` gains a canonical (D5 note).
- **E7 — Search-engine semantics.** A canonical pointing at a page on a different origin (`acewerk.com` for a `dev.acewerk.com` document) is standard cross-domain canonical usage and matches how the site's 4 non-blog dev pages already declare canonicals. No `rel="alternate"`, `hreflang`, or og:url changes are in scope.
