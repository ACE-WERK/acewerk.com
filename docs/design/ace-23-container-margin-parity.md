## 0. User Story

As a **visitor** of AceWerk on a phone or tablet, I want the content container gutters (side padding) and the top spacing under the nav to behave **identically on every page**, so that the site feels like one consistent product rather than a set of pages with subtly different framing.

## 1. The two defects (verified live)

### ISSUE 1 — mobile/narrow gutter mismatch
Every content block on every page is wrapped in the **same** element: `<div class="content-wrap site-container">`. The gutter is therefore governed by a **cascade of two `.site-container` definitions**. The governing rule (the one that wins for `main .content-wrap.site-container`) differs by page:

- **Blog pages** (`blog/index.html` + 3 post pages, all generated by `scripts/build_blog.py`): the only `.site-container` rule is the token-based, early-in-sheet rule →
  `padding: 0 clamp(20px, 4vw, 48px);` (scales with viewport).
- **services / our-team / contact**: an additional `.site-container` rule appears **at the END of the `<style>`** →
  `padding: 0 48px;` (fixed). Being later and equal-specificity, it **wins**, so the gutter is a fixed 48px at every width.

Measured `main .content-wrap.site-container` (live, `getBoundingClientRect`):

| Viewport | Blog (wrap / shell) | services/our-team/contact (wrap / shell) |
|---|---|---|
| 1440×900 | x=170, w=1100 / shell x=218, w=**1004** | x=170, w=1100 / shell x=218, w=**1004** (EQUAL) |
| 768×1024 | x=0, w=768 / shell x=**30.72**, w=**706.56** | x=0, w=768 / shell x=**48**, w=**672** |
| 390×844 | x=0, w=390 / shell x=**20**, w=**350** | x=0, w=390 / shell x=**48**, w=**294** |

Blog already matches the user's reference ("screen scaling of the containers on Blog pages"). The three non-blog pages do **not** scale. At 390px their shell is only 294px wide (x=48) vs blog's 350px (x=20).

> Note: the task body's "shell 692px / 335px / 1004px" figures described the **wrap**/shell loosely; the precise governing numbers are the **shell** box above (1004 / 706.56 / 350 for blog). The defect and its magnitude are confirmed exactly.

### ISSUE 2 — blog **post** pages have no top spacing
On a post page the first (only) content shell is `<div class="content-shell reveal">` — it has **no** `hero-shell` class, so it inherits **no** top margin. On every other page the first shell is `<div class="content-shell hero-shell reveal">`, and `.hero-shell { margin-top: clamp(24px, 4vh, 44px); }` lifts it below the nav.

Measured shell `getBoundingClientRect().y` (= nav-height + resolved margin-top):

| Viewport | Post shell (NO margin) | services/our-team/contact hero shell (WITH margin) |
|---|---|---|
| 1440×900 (nav 52) | y=**52** (mt=0) | y=**88** (mt=36px) |
| 768×1024 (nav 44) | y=**44** (mt=0) | y=**92.95** (mt=40.96px) |
| 390×844 (nav 44) | y=**44** (mt=0) | y=**77.75** (mt=33.76px) |

Post shells sit flush against the nav; the others start 77–93px down.

## 2. Decisions (FROZEN)

### D1 — Canonical gutter = the blog `clamp()` rule; unify all pages to it.
The target gutter for **every** content block on **every** page is:
`padding: 0 clamp(20px, 4vw, 48px);`
Rationale: (a) the user explicitly referenced the blog's scaling as correct; (b) it is already the value the **generated** blog pages ship with, so unifying the three hand-maintained pages to it is the minimal, forward-safe direction; (c) `clamp(20px,4vw,48px)` degrades gracefully (20px floor on phones, 48px ceiling ≥1200px) and is the site's established token-driven idiom. Rejected: switching blog down to fixed 48px (loses the mobile scaling the user wants) and a bespoke third value (new magic number, no precedent).

### D2 — ISSUE 1 fix = change the governing `.site-container` rule on the three non-blog pages to the D1 clamp.
Per file, change exactly this declaration (the end-of-sheet, currently-winning rule) from `padding: 0 48px;` to `padding: 0 clamp(20px, 4vw, 48px);`, keeping `width: 100%; max-width: 1100px; margin: 0 auto;` untouched:
- `services/index.html` — `.site-container` @ **line 522** (padding line **525**)
- `our-team/index.html` — `.site-container` @ **line 541** (padding line **544**)
- `contact/index.html` — `.site-container` @ **line 609** (padding line **612**)
Because this is the same single rule that also styles `.header-inner-wrapper.site-container` (the nav row) and the content wrap, changing it is consistent: at 1440px it resolves to 48px (no change) and only re-scales below ~1200px. The nav is still visually protected by its dedicated `@media (max-width:700px)` override `max-width:none; padding:0 clamp(16px,4vw,32px)` (see E6). **Do not** edit the `.content-wrap` rule on these pages (it is already the clamp and is not the winning rule).

### D3 — ISSUE 2 fix = give the post content shell the existing `hero-shell` top-margin rule (markup change, no new CSS).
In the **post-page** template and the three committed post pages, add `hero-shell` to the article shell class list:
`<div class="content-shell reveal">` → `<div class="content-shell hero-shell reveal">`
- `scripts/build_blog.py` — `build_post_page`, line **1245** (the **only** post shell line; do **not** touch line 1196 = blog-index hero, nor line 1203 = blog-index grid).
- `blog/dev-fixture-short/index.html` — line **669**
- `blog/dev-fixture-long/index.html` — line **669**
- `blog/dev-fixture-truncation/index.html` — line **669**
This reuses the already-defined `.hero-shell { margin-top: clamp(24px,4vh,44px); margin-bottom: clamp(18px,3vh,30px); }` rule present on all pages. Rejected alternative (a dedicated `.post-shell { margin-top: … }` rule): it would duplicate an existing token and add CSS to maintain. Using `hero-shell` keeps the fix a pure, 1-token-per-file markup parity — the article's "hero" **is** the article header.

### D4 — Single source of truth = `build_blog.py`; regenerate + hand-patch identically.
The three post pages are generated. Dev MUST (a) edit the template line in `build_blog.py` and (b) re-run `python3 scripts/build_blog.py`, then (c) **diff** regenerated output against the committed pages. Expected: the ONLY per-post-page delta is the added `hero-shell` class on the shell line (D3). If regeneration surfaces any unrelated drift, do NOT absorb silently — report it and hand-patch the three pages identically (same protocol as ACE-22 E5). The blog index and post CSS already ship the D1 clamp, so **no** blog-side gutter edit is required.

### D5 — Docs: a new unified-container spec is REQUIRED.
`docs/design/blog-design.md` (and the ACE-21/22 specs) document the blog shell **locally** but there is **no** cross-page container spec covering `site-container` + `content-wrap` + `content-shell` + `hero-shell` top-margin for all pages. A Design-owned doc must be added documenting the unified rule (D1 gutter + D3 top margin) so it is the single reference for future pages and for `build_blog.py`. (See §6, and the flagged Design task.)

## 3. Acceptance criteria (exact measured targets)

**A1 — 1440px invariance (no desktop shift).** After the fix, on services, our-team, contact **and** all blog pages, `main .content-wrap.site-container` = x=170, w=1100 and `.content-shell` = x=218, **w=1004**. Must be byte-identical to the current 1440px baseline (the D1 clamp resolves to 48px ≥1200px). No horizontal overflow (`documentElement.scrollWidth - innerWidth == 0`).

**A2 — 768px parity.** On the three non-blog pages the shell now reads x=**30.72**, **w=706.56** — exactly matching the blog at the same viewport. `overflowX == 0`.

**A3 — 390px parity + no overflow.** On the three non-blog pages the shell now reads x=**20**, **w=350** — exactly matching the blog at 390px. No horizontal scrollbar (`overflowX == 0`). The mobile nav is unchanged (nav height 44px).

**A4 — Post top spacing matches the canonical hero margin.** On all three post pages (short/long/truncation), `main .content-shell` computed `margin-top` = `clamp(24px,4vh,44px)` resolving to:
- 1440×900 → shell `y = 88` (mt 36px),
- 768×1024 → shell `y = 92.95` (mt 40.96px),
- 390×844 → shell `y = 77.75` (mt 33.76px) —
identical to the services/our-team/contact hero shells at the same viewports (currently the posts read y=52/44/44). `overflowX == 0` at all three.

**A5 — Gutter rule is the D1 clamp on all pages.** The winning gutter declaration for `main .content-wrap.site-container` is `padding: 0 clamp(20px, 4vw, 48px)` on services, our-team, contact (was fixed 48px) and unchanged on blog. Verify via computed style, not source grep.

**A6 — Nav/menu unchanged.** On all pages: nav height invariant (52px ≥769px, 44px ≤768px); `.nav-bar .header-inner-wrapper.site-container` mobile override (`max-width:none; padding:0 clamp(16px,4vw,32px)` on the non-blog pages) intact; nav logo/links/hamburger render identically (visual). The content-gutter change must not move the nav logo off its x-position in a way QA sees as a layout jump.

**A7 — SEO untouched.** `<meta name="robots" content="noindex, nofollow">` and every `<link rel="canonical">` on all touched pages are byte-identical to pre-fix (dev stays noindex + canonical→acewerk.com).

**A8 — Blog template sync (build_blog.py).** After Dev's change, re-running `python3 scripts/build_blog.py` produces post pages whose **only** delta vs the committed pages is the added `hero-shell` class (D3). No unrelated CSS/markup drift. Blog-index output is unchanged.

**A9 — No horizontal overflow at 390px** on every page (services, our-team, contact, blog index, 3 posts): `documentElement.scrollWidth <= window.innerWidth`.

**A10 — No layout shift at 1440px** on every page: the `.content-shell` box (x, w, y) is invariant vs the pre-fix baseline (A1 + A4's y on posts is the intended change and is asserted separately; services/our-team/contact y must stay 88).

**A11 — Scope guardrail (file/line).** The only edits are: the one `.site-container` padding line in each of services/our-team/contact (D2); the one post-shell class line in `build_blog.py` + 3 generated post pages (D3); plus the new Design doc (D5). No other CSS rule, media query, JS, or content block is modified.

**A12 — No-JS / reduced-motion safe.** Both fixes are pure CSS/markup. With `prefers-reduced-motion` and JS disabled the containers render identically (no dependency on the `reveal` animation for the margin to apply).

**A13 — Docs delivered.** A Design spec documenting the unified container rule (D1 + D3) exists under `docs/design/` (e.g. `ace-23-container-spacing.md`) and is the reference the QA card checks against.

## 4. Edge cases

- **E1 — 769–1200px band (non-blog).** The D1 clamp is between its 20px floor and 48px ceiling here (e.g. ~40px at 1000px), so the shell width changes smoothly vs the old fixed 48px. This is the intended scaling; QA spot-checks one mid width (e.g. 1024px) for no overflow and no abrupt jump.
- **E2 — ≥1200px (non-blog).** Clamp hits the 48px ceiling → identical to old fixed 48px. No-op; guarantees A1/A10.
- **E3 — ≤390px (all pages).** Floor is 20px; shell x=20, w=350 on 390px. At still-narrower widths (e.g. 320px) clamp stays ≥20px, shell = 320−40=280px, no overflow. Blog already behaves this way; non-blog pages now match.
- **E4 — `.content-shell` internal padding.** The shell's own `padding: clamp(26px,4vw,56px) clamp(22px,4vw,56px)` is **unchanged**; only the outer container gutter changes. Inner text measure (ACE-22 `.post-body` full-width) is unaffected.
- **E5 — Regeneration drift (D4).** If `build_blog.py` output differs beyond the `hero-shell` token, hand-patch the 3 pages identically and flag (do not silently absorb). Guard: A8.
- **E6 — Nav is the shared consumer of `.site-container`.** Because the D2 rule also styles `.header-inner-wrapper.site-container`, confirm the nav stays correct: non-blog pages carry the dedicated `@media(max-width:700px)` override that pins the nav to `max-width:none; padding:0 clamp(16px,4vw,32px)` (higher specificity), and blog pages keep their `clamp(20px,4vw,48px)` nav (no override) — both pre-existing, both untouched. QA must visually confirm the logo does not shift (A6).
- **E7 — Multiple content blocks (services/contact).** These pages have **two** `content-wrap.site-container` blocks. Both consume the same fixed-48px rule, so both re-scale together (the second block's y shifts only by the top-margin/height of the first, which is unchanged). QA confirms no inter-block misalignment at 768/390px.
- **E8 — Post `margin-bottom` from `hero-shell`.** Adding `hero-shell` also applies `margin-bottom: clamp(18px,3vh,30px)` to the post shell (currently 0). The post shell is the sole block before the footer, so this only adds bottom breathing room above the footer — a deliberate, parity-consistent consequence of D3. QA notes it is expected, not a regression.
- **E9 — Ultra-wide >1200px.** Gutter capped at 48px by the clamp ceiling; container capped at 1100px by `max-width`. Bounded; no runaway. (Matches A1.)
